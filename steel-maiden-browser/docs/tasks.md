# 任务手册

入口：手册 → 任务。五类共 454 条客户端任务：新手 130、建设 32、挑战 164、主线 78、退返 50。完整保留历史与停用配置；默认隐藏不可用条目，勾选“显示已隐藏任务”即可查看、筛选、检索全部数据。静态档案不等同账号当前可接任务。

## 数据来源

- 导出器：`../analysis_apk/tools/build_task_catalog.py`。生成 `public/data/task-catalog.json` 与 `public/art/tasks/`；表源 SHA-256 纳入 JSON，可用 `--check` 完整重建校验。
- 分类严格复用 `AwardUI.lua:882–922、1143–1155`：AchievementListInfo 的 `AWARD` 条目，以同 ID 关联 ProduceRuleInfo，再按配方标签关联 ArrangedStyle 的 `SUCCESS` 文案。2503/2502/2501/2500/2506 分别是上述五类。不是用名称、编号段或进度条类型猜分类；`DEMO_BATTLE`、隐藏触发器、狩猎任务等其他入口不混入这五栏。
- `AchievementListInfo.tags` 是旧解析器对 **显示需求组** 的误命名，不是分类标签。原生 `r_ListAchievemtProduceRules`（ARM64 `0x7ea0ac`）检查偏移 `0x70` 的领取状态；未领取时检查 `0x58` 的显示条件。`field_4` 是列表排序值。
- 解锁/前置列读取该显示条件向量；完成要求读取配方 `field_98`。删除本任务未领取锁存条件，但不删除其他门槛。跨列相同的完整谓词只显示一次；原始需求组 ID 留在每行 `source` 中。
- 完成要求不是仅抄任务说明：等级从 CraftInfo 取名、通关评价从 ChapterLevelInfo 的 Quest 字段反查节点并用 `LETTER_RESULT` 解码评级、鹰标/金桨分开、获得历史及培养统计保留人数/等级门槛。无法直接命名的完整单项谓词，与唯一对应任务原文精确关联，不模糊匹配。游戏原文可单独展开对照，例如停用的“空中霸王”说明误写突袭/鹰标，实际条件是金桨。
- Quest 记录类型 3 保守显示为“关卡进度记录”，不将其混同类型 9 的评价条件。类型 17 的统计中，5 是亮星阶段，不是车辆稀有度；4 是获得历史，7 是培养等级。标签 800 是钢舞姬集合，801–806 是车型集合，811–813 是原始稀有度集合。
- 类型 9 时间窗是 **起点 + 持续秒数**，不是两个时间戳；原生回调 `0x6ef528` 的 `0x6ef684–0x6ef690` 将两者相加后比较结束边界，负持续值视为无结束边界。导出显示北京时间；不判断服务器实时活动状态。
- 一次性记录 1218 的唯一配置写入源为 AwardGroup 26 / AwardTable 13 / ProduceRule 470，与 Fund 4246「新手选人凭证」一起发放。因此“募兵硬币”的前置显示为“尚未触发新手选人凭证发放记录”，不是错误地写成无条件，也不根据名称猜成持有募兵硬币。

## 默认隐藏与游戏显示条件

- 数据不删除、不改分类、不丢奖励。`taskAvailability.ts` 在显示与搜索前统一判断隐藏原因；开关恢复全部 454 条，分类数量和奖励筛选随之更新，隐藏原因显示在任务名称下。重置筛选回到默认隐藏状态。
- 配置等级高于 CraftInfo 实际上限的 67 条任务默认隐藏；类型 9 的时间窗使用结构化秒级时间戳判断，开始包含、结束不包含，无结束时间支持无限期。已过期和尚未开放的记录都可通过开关显示；前端每分钟更新一次判断，导出文件不随运行日期变化。
- 以北京时间 2026-10-11 12:00 为校验时点，默认显示 370 条、隐藏 84 条：67 条不可能达到的等级门槛、14 条过期时间窗、2 条尚未到期的开放窗、1 条已确认停开关卡任务。不能由静态资料确定的服务器活动状态不擅自判定停用。
- **赫鲁晓夫之梦（651010）**：`AchievementListInfo.tags=[4735104]`，该需求组是 `type=3, [8,1,1,2147483647]`，即账号须持有 Quest 8 的历史参与记录。这是**显示条件**，不是挑战关卡的完成条件。领取要求另外包含 `3:1411001:3:1:2147483647`，关联地图 245「沃尔夫斯凯尔悬赏（初级）」的进度记录。地图进入条件又含 `7:51:1`，需要活动 51「攻势盛典」处于开放期。用户确认该关卡早已停止开放，因此仅对此任务记录 `retiredReason`；不把 Quest 8 记录直接伪装成服务器当前活动状态。导出断言验证上述任务、地图、活动的对应关系。
- 原生证据：`patch/_1.18/RanaScripts/ui/AwardUI.lua:1143` 调用 `ListAchievemtProduceRules("AWARD", true)`，`:1170` 排除已领取条目。ARM64 `r_ListAchievemtProduceRules @ 0x7ea0ac` 在 `0x7ea1a4` 读取领取条件 `+0x70`，未领取时在 `0x7ea1ec` 读取显示条件 `+0x58`，经 `Property_Set::checkFailedDemands` 检查，不通过就不加入列表。`r_IsCampaignActive @ 0x7fcd50` 调用 `Social_Set::findActivingCampaign`，说明活动开关还依赖实时活动集合，不能仅用本地旧排期替代。
- **国庆每日登陆福利（831010）**：配置时间为北京时间 2015-10-01 00:00 至 2015-10-08 00:00，默认隐藏来自日期判断，不是硬编码任务名称。

## 奖励

按照配方 → AwardTable → AwardPool → AwardGroup 逐项导出。当前 454 条均为全权重单结果，无条件分支；结构变化会触发断言，不能把随机结果累加成保底奖励。

- 类型 0 / Craft 1：指挥官经验，复用 AwardUI 的 `zjm-006`。
- 类型 1：物资，名称与原版图标来自 FundTypeInfo。标签 83 的装备额外按 Fund 标签 → ArrangedStyle 的 `EQULEVEL` → 数值项 1 导出 `equipmentLevel`，显示 `S1`、`S2` 等。复用 `FundUI.lua:7984–7986` 的取级与 S 前缀逻辑，不按 ID 或名称猜测。48 处装备奖励全部与装备手册的 fundId / level 交叉验证，搜索支持“装备名 S2”。
- 类型 2：钢舞姬或其他道具，经 CapsulePhaseInfo → UnitAppearanceInfo → roleModelInfo 解出名称及图标。食物不是装备，不追加 S 等级。
- 类型 3：内部进度写入，不作为物资展示。无物资的保留条目明确提示“仅记录任务进度”。

例：建设“战地废墟”要求司令部 2 级，奖励金币 ×50；“夏日海豚”时装退返为时装退返币 ×219、认购币 ×73。原始数据中 67 条带停用等级门槛，18 条含时间/活动限制。未使用自制奖励图标，当前无缺失素材或未解析条件。

## 界面及验证

使用四列表格：任务、完成要求、奖励、解锁/前置要求。表格两侧各留 24px 间隙，600px 及以下窄屏各留 12px；没有卡片外框、最大高度或内部纵向滚动，直接跟随页面滚动。桌面表头粘在页面顶部，窄屏只保留横向滑动以免截断列内容。支持五类切换、奖励名称筛选、条件类型筛选、跨名称/要求/前置/奖励/编号的即时搜索，空格分隔词为 AND。按客户端顺序排列，每页 30 条，翻页回到表头，长条件可展开。

任务数据仅在进入页面时加载；失败可重试，不阻塞其他板块。文本以 React 普通文本渲染，不执行配置中的 HTML。

验证命令：`npm run verify:tasks`、`npm run audit:tasks -- http://127.0.0.1:56501`、`npm run audit:navigation -- http://127.0.0.1:56501`、`npx tsc --noEmit`、`npm run build`。
