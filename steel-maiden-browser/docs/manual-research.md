# 研发路线手动模式与统一方形头像

2026-10-31。入口：钢舞姬 → 研发路线 → 手动模式。完整模式仍为默认，两种模式分别保留画布；手动画布保存在当前页面会话中，切换栏目、双击查看配方后返回仍保留，刷新页面会重置。

## 操作与关系语义

先指定一名钢舞姬，仅显示该车。每个节点上方／下方都有展开按钮，弹窗分别列出真实直接上级／下级，单选一辆并确定后添加对应连线。任意已有节点均可反复展开其他分支。T-60（6495）初始下级候选6位，选T-50（6444）后只出现T-60→T-50，不自动插入KV-13、T-26等其他共同前置。

手动画布表示用户选择的研发关系，不将某条路径宣称为完整研发配方。弹窗展示本车在对应关系中的期数／等级要求，并提供完整条件提示；双击节点头像跳转到研发配方页查看全部前置和消耗。

同一车辆只创建一个节点；选择画布内已有车辆时只添加新连线。已添加关系禁用；会形成有向回环的候选禁用。多个配方中相同的直接邻接关系合并为一个候选，内部保留recipeIds，未按目标名称把不同车辆合并。节点及箭头按真实依赖方向自上而下排列。

支持撤销上一步、只保留起点（也可撤销）、清空／重新指定起点、回到起点、空白处横向与纵向拖动。拖动继续使用逐帧合并与instant纵向滚动。实装开关过滤不可见节点及不再有效的连线，并隐藏与起点断开的节点；过滤本身不删除已保存方案，重新包含后恢复。若在过滤后继续编辑，会从当前可见图形成下一步快照，旧快照仍可撤销找回。

## 头像与分享

研发配方的索引、选中角色、前置、下级、速查表，研发路线的候选、当前车、完整图及手动图均使用图鉴的方形头像图层：原版边框、方形头像、稀有度、车种、魔改费用。`TablePortraitImage`与`TablePortrait`共用`PortraitLayers`，前者为非交互span，可放在已有按钮中，不产生嵌套button。

`ResearchPortraitProvider`按卡牌ID关联原角色资料，不凭头像文件或同名人物猜稀有度和魔改费用。默认立绘及皮肤切换仍由原图鉴组件处理，研究页面仅使用默认头像。

完整图和手动图的PNG均通过`portraitCanvas.ts`使用同一批素材及原版图层坐标合成；不再用旧横条头像裁切替代方形卡面。手动图按完整已选图的几何信息出图，包含所有已选节点、箭头、起点与关系数量，不受当前滚动位置限制，也不包含展开按钮、选择弹窗或未选候选。导出沿用`deliverPng`：浏览器复制PNG，现有Android桥保存相册。最大边12000、总像素3600万，必要时同比缩小。

## 分支位置与连线修正

原布局在同一层使用节点加入顺序，导致晚加入的MOWAG（9895）落在T-50分支的右侧。现在根据相邻层的上下级位置交替排序，再用相邻交换降低两侧实际交叉数，保留找到的最佳顺序。单一父级的下级会按分支聚拢；共享节点仍保持唯一，数据及真实连线不变。

跨多层的连线在中间层预留空槽，经过卡片之间的通道，不直接穿过中间卡片。节点出入端口按相邻节点顺序分散排列。页面和PNG均使用`manualEdgeCurves`／`manualEdgePath`的同一组几何数据，不能仅调整其中一种输出。

`npm run verify:manual-layout`覆盖截图9节点／8连线、576种父级和下级加入顺序、共享汇合、跨层连线避让及无卡片重叠；截图分支交叉数为0，下级顺序为BM-24T、MOWAG、KV-4 KTTS、261-3工程。`npm run audit:manual-layout -- <网址>`按截图的操作顺序实际展开，检查页面位置、SVG路径、完整PNG、移动端和资源加载。截图与分享图保存在`.cache/manual-layout-branches.png`、`.cache/manual-layout-share.png`。

交叉优化保留实际指标`crossings`。复杂共享网络可能无法仅靠分层内排序完全平面化，不应把任意图均为零交叉写成通用数据规则。
