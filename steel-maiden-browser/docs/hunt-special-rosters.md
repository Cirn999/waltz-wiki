# 狩猎任务 P-30 / P-31 / P-32 名单修正

2026-09-25，依据当前 `patch/_1.18/config` 重新核对，不根据立绘外观推测。

| 任务 | 条件 | 符合条件的车辆数 | 条件文字 ID | 编队条件 → 单车条件 → 车辆标签 |
| --- | --- | ---: | --- | --- |
| P-30 | 兽耳 | 43 | 700785 | 138566081 → 880 → 861 |
| P-31 | 黑色头发 | 54 | 700810 | 138568301 → 881 → 862 |
| P-32 | 戴眼镜 | 21 | 700811 | 138568321 → 882 → 863 |

三项任务均要求编队中至少有 6 名符合条件的钢舞姬，在「出击 → 争霸」进行一次挑战并获胜。数量以当前档案库中的车辆条目计，不合并同名人物的不同车型。

## 原因及修正

旧导出脚本把条件文字 ID 写成了 700786 / 700811 / 700812，全部偏移了一项。实际分别对应「不能有航空钢舞姬」「戴眼镜」「需要 IV 号坦克 G（液力）型」，却套用了兽耳、黑发、眼镜的固定名称，产生了 57 / 21 / 1 辆的错误名单。

现在先完整解码 `AchievementListInfo.dat`（原生读取函数 `0x88310c`，检查所有记录及 EOF），按任务名称找到任务及描述，再以描述中的完整编队要求匹配 `ArrangedStyleInfo.dat`。继续沿类型 20 编队条件、类型 12 单车条件找到 `CapsuleTypeInfo.group_b_ids` 标签，生成实际名单。

生成时校验任务名称、条件原文、至少 6 人、条件极性和车辆标签；遇到不一致立即报错。全量和局部数据生成共用同一个带校验的导入模块，不再静默导入错配名单。

共享的 `maidens.json` 中全部车辆的 `huntTraits` 已刷新，所以属性表、详细信息排名、图表选车筛选同时更新；未改动任何属性数值、图标、魔改费用等其他字段。

## 复现与验证

- `npm run prepare:hunt-traits`：重新解析客户端，仅更新狩猎任务字段。
- `npm run verify:hunt-traits`：逐车核对配置、报告、前端数据，并验证旧错误输入会被拒绝。
- `npm run audit:hunt-traits -- http://localhost:3100`：浏览器测试三个筛选入口、每个入口的三项任务。

完整名单及可审计的条件链位于 `analysis_apk/output/hunt_special_lineups/` 下的 JSON、CSV 和 Markdown 报告。
