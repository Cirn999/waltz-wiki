# 道具手册

入口：手册 → 道具。按原版 FundUI 仓库分类收录 tag 81 且带 82（资材）或 99（活动道具）的 413 条记录，包含历史活动道具，不推断服务器当前开放状态。名称来自 StringTable；图标来自 FundTypeInfo 的原生资源，优先仓库图标类型 9、回退类型 5。4229 菲亚特兑换道具的原版资源为透明 tm-001，明确标为原版无图，不冒用其他素材。

导出脚本：`analysis_apk/tools/build_item_catalog.py`。保留来源文件 SHA256、原始标签、消耗配方及奖励表 ID。使用 FundAchievementInfo 原文；根据 ConsumeGroup/ProduceRule/Commodity 链显示兑换消耗用途，不将背景文字当作战斗效果。缺少可读说明的记录明确标记，不捏造用途。

使用奖励依据仓库 tag 773 及旧版 1702/1704 使用配方，选择一次消耗一个的规则，不误用十连规则。只有无条件、全额触发、唯一确定组的奖励列为固定获得；其余列为随机／条件奖池候选，不相加、不称全部必得、不猜概率。过滤内部 Quest 记录；自动战斗仪的冷却效果采用原版说明，其他功能类效果与背包物资区别显示。支持装备奖励附原生 EQULEVEL（S 等级）。亮星、授勋材料用途通过 CapsuleFacultyTrainInfo 的消耗组确认。

T/H/I/S 地雷：DemandGroup 2094 要求四种各至少一个；Commodity 549、35218 的显示条件包含该组，对应探雷标兵。没有地雷消耗配方，因此标明购买资格、另行购买、地雷不消耗。

时装共享 Train 标签只说明角色，不能据此把该角色所有皮肤都当作单个时装盒的内容。

验证：`npm run prepare:items`、`npm run verify:items`、运行开发服务后 `npm run audit:items`。卡片使用原生 details 展示长用途、随机奖池及背景说明；分类、用途及全文搜索作用于完整数据，分批渲染不截断检索范围。

## 仓库出售（2026-10-11 核对）

413 条资材／活动道具中，127 条有明确仓库出售配方。依据 `patch/_1.18/RanaScripts/ui/FundUI.lua:10381–10405`：道具具有 tag 1701，匹配同时具有 1701、1501 的 ProduceRule，且消费对象就是当前道具；不可把商店兑换、强化或任意消耗配方视为出售。本次全部出售配方均仅消耗该道具 1 个，产出为固定物资。旧银币券、航空联票的奖池 flag 为 0，但只有一个全权重无条件选项，仍为确定结果；多选／条件奖池不得合并成必得出售结果。

单独输出 `sale.quantity/rewards/conditions`，原名、原生图标及数量复用奖励组件，在卡片显示“出售1个可获得”，不混入“使用后获得”。出售所得名称纳入搜索。`source` 保留出售配方、奖励表、条件组；Craft、ChapterLevel 和关卡目录加入来源哈希以追踪条件释义。

- XM551谢里登原型车徽章（4436）：配方1179 → 消耗组1892（徽章×1）→ 奖励表1669 → 奖池1677 → 奖励组1668 → 特战招募卡（4231）×4。4428–4443 共16种车辆徽章均为4张。
- 空勤调令×1 → 源铁×60；250K/500K/1500K型银币券分别为25万/50万/150万银币；其他出售所得还包括密码子、量子精华、军用罐头、认购币、空勤调令。

出售数据保留历史记录，与本页其他道具一样不代表服务器当前开放状态。验证包含全部127种覆盖、16枚徽章、旧式单选奖池、两条前置条件、四条仅有标记的记录，以及页面出售区、按出售所得检索、固定卡片尺寸。

## 兑换去向弹窗

216 种道具新增“查看兑换”入口，共关联 1,837 条原版商品方案。`item_exchanges.py` 按 CommodityInfo → ProduceRule → ConsumeGroup / AwardTable 导出完整道具成本及确定奖励；同商品不同价格／条件的方案分别保留，不按名称合并。仓库使用、出售规则排除在外。保留商品 ID、配方、奖励表、显示条件、执行条件与非道具消耗原文；非道具限制不冒充货币。静态配置包含历史记录，不代表服务器当前开放。

- 水晶贝：34 项，其中26项为车辆；霍尔特150T为水晶贝×80；破损情报×2消耗水晶贝×1；限量物资为粮票×3和250K型银币券×16，消耗水晶贝×9；虹氨酸×15,000消耗水晶贝×7。
- 奖池仅有一个全权重、无条件选项时才列为固定所得；随机招募等不展开成“必得车辆”。Quest 内部进度不冒充背包物品，纯功能项显示原生商品图标及功能类别。
- 车辆奖励通过 capsule ID 直接关联图鉴数据，弹窗直接使用 `TablePortrait`，保留原版头像框、稀有度、车种、魔改费用。舞装 fund tag84 复用获取途径的最具体 capsule 标签映射，明确标注“舞装”，不将其误写为立即发放整车。
- 弹窗支持搜索、内部滚动、窄屏布局、Escape关闭和焦点还原；没有背景点击关闭处理，避免拖动滚动条时误关。点击车辆头像先关闭兑换弹窗，再打开详情。卡片固定360px高度不变，兑换按钮在滚动正文之外。
- 历史商品图标 grbz-139/148/151/155/156 在现有原版资源中缺失，明确显示缺图占位，不伪造图标；透明 tm-001 保持原版无图。其余材料和奖励展示原生图标与数量。

回归测试包含全部兑换引用／消耗关系、车辆 ID、图标文件、舞装映射、水晶贝数量、多材料成本，以及桌面/移动端弹窗、头像组件、搜索、滚动、关闭及原有道具功能。

兑换窗口使用紧凑布局：桌面四列，单项奖励采用左侧完整头像／图标、右侧名称与消耗的横向排版，去除重复名称和底部撑高空白；多项礼包保留全部奖励并按内容展开。1100/850/560px断点分别减少为三／二／一列。修改后必须执行 `npm run build` 更新根目录启动器读取的 `dist/client`，并在静态构建页面运行道具审计，不以开发页验证替代启动器版本验证。
