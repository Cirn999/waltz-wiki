# 关卡档案

## 入口与范围

顶部导航“关卡”包含“关卡一览”和“收益一览”两个子栏目。“关卡一览” → 六类出击入口 → 地图列表 → 战斗节点详情。

- 战役：主线第 1–26 卷（104 张地图）、特殊任务（24 张）、战役捷径（28 张）。后两类分别按客户端顺序从 1 连续编号，列表和详情标题一致。
- 活动：121 张地图。材料、补给、幸运、积分合并为“资源行动”（42 张），按战车残骸、秘密计划、演算模块、实验人偶、经验道具、源铁、军牌分组。挑战任务与特殊补给合并为“挑战行动”（45 张），按游戏原生行动名称分六组；其他活动仍单列。
- 突袭、空袭：各展示 40 张普通地图，不提供模拟关卡入口；静态数据仍保留各 40 张模拟图供来源校验。
- 信使计划：18 卷、36 张地图。
- 多福莱尼：普通、模拟地图各 20 张。
- DEMO、HIDDEN 和未被地图引用的节点单独放入“客户端附录”，不混进普通战役。

当前数据来自 515 条 ChapterInfo 记录、1,274 条 ChapterLevelInfo 记录。3 个未关联节点放入一张明确标注的附录卡片，导出共 516 条地图记录（含页面隐藏的 80 张突袭／空袭模拟图）。页面展示的是客户端静态收录内容，包括历史活动，不模拟服务器当前开放状态。

### 收益一览

- 覆盖客户端全部 28 张普通战役捷径，默认按捷径 1–28 排列。展示燃油消耗、总银币、总密码子、银币／燃油、密码子／燃油和装备掉落；六个数值／序号表头支持升降序，地图名称打开同一详情弹窗。
- 直接复用 `stageIncome.ts` 的节点收益结果，按各节点各结算一次汇总；入图燃油读取 Fund 4，一张地图仅计一次。单位收益以未舍入的总收益除以燃油，显示两位小数，排序用原精度；零燃油时显示“—”。不计装备折价、随机或临时奖励。
- 与关卡一览、详情页共用主线进度档位与 S/A/B 评价，使用相同的全局持久化设置。切换设置立即重算表格。
- 装备来自节点的已解析掉落明细，仅保留“装备”，按 Fund ID 去重、合并评价范围；同名不同部位不得合并。当前 78 种装备支持名称搜索、部位查找与多选或逻辑筛选，也可直接点表中装备快捷筛选。
- 按全部可能掉落匹配筛选，卡片标注可掉落评价及当前评价不可掉落状态，不将“可能掉落”解释为必掉。表格不放在固定高度容器中，全部行随页面自然展开，桌面表头吸附在导航下方；小屏仅保留必要的横向滚动，不限制表格高度。装备筛选选项超高时仍独立纵向滚动。
- 回归命令：`npm run verify:stage-yield`（28 图 × 25 档 × 3 评价）、`npm run audit:stage-yield -- http://127.0.0.1:3101`（导航、筛选、排序、详情同步、持久化、素材与窄屏）。

### 紧凑详情布局

宽屏下总收益在左、进入条件在右，共用下方战斗概览的列宽；“第 X 战”、节点切换按钮及上一／下一按钮一并整合到敌人配置卡片顶部，卡片外不再占用独立切换行。左侧依次排列本节点收益和敌人配置，两者等宽；右侧地形卡片从节点收益一行开始，并与敌人配置底边对齐。布局按内容自动伸缩，不写死卡片高度；没有节点收益时也不保留占位。视口不超过 900px 时改为纵向排列，节点按钮过多时在卡片内横向滚动，上一／下一节点会同步滚动至当前按钮。

地形原图在宽屏为 64×52px、debuff 图标为 48×48px；手机上分别为 48×40px、40×40px，均等比展示、不裁切原图。debuff 名称和说明统一用 11px 字号，行间保持紧凑。

进图消耗合并到“地图进入条件”卡片中，位于标题下方、条件列表上方，保留物资图标、完整名称及数量；详情顶部不再单独占用消耗卡片。列表缩略图右上角的消耗标记保持不变。

突袭、空袭、信使计划、活动的详情卡片隐藏“主线通关进度”，保留“结算评价”；有总收益卡片和仅有评价控制条的布局均适用。相应收益说明改为“按所选评价汇总”。只调整详情控件显示，不重置全局保存的主线进度，也不改动收益计算；战役、多福莱尼及外层全局进度选择保持原样。

## 距离与效果

- 水平作战距离读取标签 3309 技能的参数 3036 / 3039 / 3042，按炮击 → 接近 → 缠斗展示；例如巷战为 500 → 100 → 50 m，山脉为 8000 → 5500 → 3000 m。复用 `ChapterUI.lua:1660` 的 `pvp-012` 原版距离图标。
- 作战高度读取标签 3310 技能的参数 5006 / 5009 / 5012，它们不是另一组水平“空战距离”。复用 `ChapterUI.lua:1748–1800` 的 `jl-017` 原版高度图标。网页以 `altitudes` 导出，并与距离一样直接展示三个阶段值，不再仅显示范围：岩地山脉为 5000 → 4000 → 3000 m，巷战为 350 → 200 → 120 m。39 种地形均校验完整，所有地图节点共享对应地形配置。两行共用阶段顺序标注，窄屏不隐藏中间阶段。
- 地形效果由 `stage_terrain_effects.py` 导出。按 `FieldImplementTypeInfo.style_ids → ArrangedStyle ENV_ITEM → 子编排 TITLE` 读取名称和顺序，**不再使用旧 SkillDesc 的名称、说明或效果组合**。“空旷 / 回声 / 河流”统一改为游戏中的“广阔 / 暴露 / 涉水”；浅滩丛林、浅滩丘陵不再误带旧技能说明中的“硬地 / 碎块”。39 份地形配置分别导出 18 种陆钢效果（标签 4712，`effects`）和 17 种空钢效果（标签 4708，`airEffects`），不混用两个作用范围。筛选依据与 `ChapterUI.lua:22848–22853` 的编排／角色标签交集一致。
- 优先读取游戏帮助页“地形造成的影响”：ArrangedStyle **1378023 / MANUAL → StringTable 701256**。这是用户截图对应的原文，包含 13 种效果，导出逐行提取并校验不同地形示例中的重复定义一致。参见 `SundryUI.lua:4255–4256`、`ChapterUI.lua:24658–24659` 的 MANUAL 文本读取。只去除字体、图片、换行标签，不改写“有所 / 大幅”“到…结束为止 / 从…开始之后”等含义，也不猜测百分比。
- 不可全量改用旧 `ENV` 文案：它仍把“突袭”写成装甲下降、“积雪”写成易受暴击、“冻结”写成回避下降、“硬地”写成易受暴击，与帮助页及各自的 `ANTI` 状态不符。帮助页原文分别是“整个战斗过程中更容易受到暴击”“整个战斗过程中回避有所下降”“整个战斗过程中受到伤害有所提升”“整个战斗过程中装甲有所下降”。
- 帮助页未收录的后期效果逐项核对：涉水、远隔、潮气、昏睡读取与 `ANTI` 一致的 `ENV` 文案；迟钝的旧 `ENV` 错写为装甲下降，使用 `ANTI` 原文“易被暴击”（与 SkillDesc 3000017 的受暴击描述一致）。未来出现未审核效果时导出失败，不自动套用旧说明。
- 效果图片从同一子编排的 `ENV` 读取，复用 `dxtz-*` 地形原图；参照 `ChapterUI.lua:23326–23331`。远隔、迟钝未配置专用 `ENV` 图片，使用其 `ANTI` 状态图标。导出保留 `styleId`、`nameStringId`、`descriptionSource`、`descriptionStringId`、`iconSource`，可追溯每条文字和图标的来源，不注入客户端 HTML。
- 敌人只展示客户端原名、车种、头像与可见等级；保留“？？？”和未知单位的原始名称，不推算属性。

### 地形手册与陆空切换

“手册 → 地形”与关卡共用 `stage-catalog.json`。地形名按 `TERRAIN_TEXT` 原始顺序直接拼接，例如“草地平原”“岩地巷战”，不再倒序或插入间隔点；因此关卡引用也同步使用游戏名称。

- 手册默认陆钢，可切换为空钢，效果、图标和搜索匹配范围随之切换。空钢的 17 种名称、图标和描述统一读取空钢帮助页 **ArrangedStyle 1378036 / 1378037 → MANUAL → StringTable 701279 / 701281**，不再使用旧 `ENV` 简称或 `ANTI` 状态图片。解析原文中的 `tjsx-*` 图标并导出原版素材；例如草地丘陵依次为“干燥、静电、风阻”，使用 `tjsx-020 / 078 / 077`。不添加未确认的精确幅度。
- 空钢 Style 188 的旧 TITLE 为“晴天”，帮助页正式名称为“干燥”。输出保留 `legacyNameStringId`，`nameStringId`、`descriptionStringId` 与 `nameSource`、`descriptionSource`、`iconSource` 指向实际使用的帮助页。包括风沙“有所提升”、积云“更容易受到暴击”、植被“武器的对地效能有所下降”等，均采用空钢手册原文，不套用旧 ENV 文案或陆钢描述。
- 显示顺序从两页中的 20 个示例提取前后关系；生成时校验重复定义一致、效果完整、排序无冲突。**效果归属仍按每个地形的空钢 ENV_ITEM 配置**，不把帮助页的通用示例覆盖到所有同名变体：例如浅滩丛林的手册示例是“浸蚀、风沙、植被”，而当前配置为“夜幕、积云、植被”；这处源数据差异保留配置归属，不凭示例改写实际绑定。
- 名称右侧按炮击 → 接近 → 缠斗显示作战距离（陆钢）或作战高度（空钢），数值和图标沿用关卡数据，单位为 m。
- 合并仅限当前陆空视角下名称、效果和作战参数相同的配置，每张卡片只显示一个代表性地形图标。孢子平原 30/53、孢子裂谷 31/54 不再并排显示重复图标，原数据与关卡对应的图片仍保留。
- 陆钢合并后 35 张卡片；空钢为 37 张，因为泥地巷战 8/51、雪地巷战 7/52 的空钢 `ENV_ITEM` 配置不同。空钢模式下保留这些变体并标注配置编号，不将它们的效果叠加或凭技能名称补齐遗漏的 UI 条目。
- 回归：`npm run verify:terrain-handbook`、`npm run audit:terrain-handbook`、`npm run audit:terrain-effects -- http://127.0.0.1:56501`。覆盖全部地形、陆空效果、三阶段数值、原版图片、切换与检索、孢子去重、名称全局一致、缩放和窄屏。

## 地图进入条件

`stage_requirements.py` 只为地图导出 `requirements`。按用户要求，不展示各战斗节点的推进条件；切换节点时地图条件保持不变。条件区位于地图详情正文顶部，等级、鹰标／金桨、阵容和才艺要求紧凑排列，前置地图保留 B／A／S 评价区别。国籍、车型、才艺、金桨、鹰标和准入道具复用客户端图标。

- 读取地图**首节点**的 `demand_group_ids`，再并入相应 `STORY` 模式的额外门槛。例如第 26 卷的 5 枚鹰标、信使计划第 9 卷的测试证不能仅靠节点表覆盖。合并后按完整谓词去重。
- 类型 1 是科技／建筑／账号等级：Craft 1 为指挥官，18501 为司令部。名称从 CraftInfo → StringTableInfo 读取。
- 类型 3 是 Quest 评价／累计值。`r_GetChapterLevelQuestId`（`0x7df16c`）读取 ChapterLevelInfo 偏移 `0x9c`，序列化对应 `raw_scalar_3`；通过此字段反查前置地图，不能用固定编号偏移。评价 51 / 70 / 92 对应 ArrangedStyle 的 B / A / S。同一卷全部地图要求同一评价时合并为一行，完整地图名保留在悬停说明中。
- `r_GetQuestIdTags`（`0x8253cc`）实际读取 QuestAchievementInfo 中的标签向量（旧解码器暂命名 `achievement_ids`）。AssaultUI 用标签 7／49 分别识别鹰标／金桨，图片为 `kjtx-007`／`kjtx-040`。多福莱尼 Quest 71／72 的累计评价分别用于前十图／后十图；“前段／后段”是档案库的区分标签，不是额外的玩家属性。
- 类型 19／20 的才艺、阵容条件按**完整类型与参数**匹配 ArrangedStyle `RAID_XQ` 的单项需求和中文说明。保留“或”“至少”“不超过”等原文逻辑，不根据车辆名称猜测。字体标签剥离，图片转换为受控文本／图片节点，不直接注入客户端 HTML。
- 类型 5 是道具数量，不是才艺。`[0, INT_MAX]` 的库存占位条件不展示；非零要求保留道具名、数量和图标。
- 类型 7 是活动开放状态，类型 9 是时间窗。展示静态条件，不判断账号是否满足或服务器是否正在开放；常见历史时间窗按北京时间标明。群岛活动的 302／304 入场计时表示资格仍有效，不应写成“等待冷却结束”。
- 类型 6 的标签 11 计时与类型 18 的标签 11 计数属于单次出击流程控制，按用户要求不展示。它们不是历史通关标志。已用原生需求分发表 `0x11f3738` 及回调 `0x6ef1f4` / `0x6f0084` 确认；不要以后误改成“通关前一节点”。

原生追踪保存在 `../analysis_apk/stage_requirements_native/`；表来源哈希纳入 JSON。未知需求类型或存在歧义的阵容文本会使导出失败，不静默省略。回归样例包括“新的旅途05”的指挥官 75 级、4 鹰标、演艺总和 5、至少一名重坦，空袭“菲的任务”的 4 金桨，以及 24-4 的司令部 20 级、指挥官 73 级和 24-3 B 评价。

### 队形 S 奖励

`stage_formation_rewards.py` 为突袭 21–40 导出独立的 `formationReward`，在进入条件卡片内单列“队形 S 奖励要求”，说明本场需取得 S 评价且同时满足所列阵容条件，并显示原版物品图标、名称与数量。它不是进图限制，也不并入基础掉落或银币／密码子收益。

- 原生分支见 `patch/_1.18/RanaScripts/ui/AssaultUI.lua:1973–1983`：Quest 标签 95 走进图限制布局；不带该标签的普通突袭走队形奖励布局。不能只按关卡名称或数字判断，也不能把早期关卡仍残留的奖励配方当作生效的队形奖励。
- 奖励读取同文件 3643–3666：首节点 `raw_scalar_3` → QuestAchievementInfo 标签 → 标签 96 的 ProduceRuleInfo，`field_c8` → AwardTableInfo → AwardPoolInfo → AwardGroupInfo。只支持当前确认的单结果池；保留 Fund 数量，排除类型 3 的内部 Quest 评价更新。
- 条件读取同文件 4792–4817：Quest 标签 → ArrangedStyle 的 `RAID_XQ` → number entry 5 原文及 demand。导出严格校验这些完整谓词与奖励配方中的类型 19／20 需求完全一致。沿用该关卡自己的说明，保留至少／不超过／国籍或逻辑，不复用其他关卡的同谓词文案。
- 突袭 21：演艺合计 ≥5、技工合计 ≥4、至少 1 名中坦，奖励 N1 图谱 ×6。突袭 34／35 有两种奖励（图谱及心契核晶），全部展示。
- 已核对全部 40 个普通空袭：当前配置没有关联的队形奖励配方。空袭 1–29 的标签 95 及原有进图阵容条件照常保留；30–40 也没有此奖励，不凭空添加。
- 回归：`npm run verify:stages`、`npm run audit:stage-formation-rewards -- http://127.0.0.1:56501`；覆盖所有 20 组物品数量、上下限／或逻辑、与进入条件分离、空袭排除及桌面／缩放等效视口／手机布局。

### 入场消耗与资源行动

## 掉落类型与边界

奖励项类型并不是统一的 Fund ID：

- 0：Craft / 账户成长，不是物品。
- 1：Fund / 道具物资。
- 2：Capsule，原始表中混有旧角色条目和经验给养，不能直接作为最终掉落展示。
- 3：任务进度；4：冷却更新；其余账户和流程更新也不作为物品显示。

这一区分由本地 `libasgame.so` 的 `generateAwardItemCraft`、`generateAwardItemCooldown` 和 `getResourceDataFromAwardItemVec` 分支核对。尤其不能将类型 0 的指挥官经验误映射成同编号物资。

### 2026-09-30 掉落预览修正

旧导出仅遍历奖励图，遗漏了原生预览的过滤步骤，错误包含了零权重条目、常规结算资源、经验给养和旧角色条目。现在应用以下规则到全部节点：

1. `AwardTableInfoReader::getAwardGroup`（`0x8b6404`）在 `0x8b64f8` 跳过权重为 0 的分支。例：24-4 首节点的 IS-1 舞装和“内舱”电子侦察仪均为零权重，不应出现。
2. `ChapterUI.lua:2039` 只收取 `GetFundType(...) == 5` 的物品。`r_GetFundType`（`0x80df5c`）读取原生结构偏移 `0x28`，对应当前解码器的 `raw_field_5`，**不是**早期暂命名为 `fund_type` 的字节。因此银币、密码子等类别为 4 的常规结算资源不展示。
3. `ChapterUI.lua:2010` 隐去 deployTag 3 的经验给养。档案库不列直接角色掉落；角色条目使用带标签 84 的 FundTypeInfo 中明确的关联 Capsule ID（`raw_field_10`）归并到相应舞装，并与奖励池已有舞装去重，不按名称猜测或固定 ID 偏移转换。
4. 装备从 Fund 标签匹配 ArrangedStyle 的 `SHEBEITUJIAN_PAGE`，读取部位名（entry 5）并复用装备图鉴的游戏部位图标。

24-4 首节点固定回归样例：`fund:8367` 电子侦察仪（炮架）、`fund:8317` 弹药水套（炮架）、`fund:39411` SU-18 自行火炮舞装、`fund:39271` SU-76 舞装、`fund:39421` M3A1 轮式侦察车舞装、`fund:3203` 钛糖（保留客户端正式名称）。

当前导出包含 287 种预览物品，没有未解析物品或舞装关联。列表仍合并基础及各评价奖励池，去重为“可能掉落”；账号相关条件保留静态可能集合，不假设当前账号状态、不相加分支数量、不猜测掉率。

### 收益档位与战斗评价（2026-10-01）

数据升级为 schema 2。`stage_income.py` 保留原奖励表、奖励池、需求组的关联，由 `app/stageIncome.ts` 按全局进度和评价计算；不将特殊任务的线性公式套用到其他地图。

- 收益范围：类型 0 / ID 1 的指挥官经验，类型 1 / ID 1 的银币，类型 1 / ID 2 的密码子。经验图标遵循 `AwardUI.lua:1447–1451` 使用 `zjm-006`；银币、密码子使用 Fund 的 resource type 5。
- 只导出真实奖励档位：尚未完整通关第 1 卷、完整通关第 1–23 卷、完整通关第 24 卷及以上，共 25 档。需求组通过主线末节点的 Quest 字段反查门槛；通关 26-1 与完整通关第 24 卷属于同一奖励档位。没有要求玩家填写精确地图或账号信息。
- 全局进度、评价保存在 `steel-maiden-stage-income-v1`。地图列表和详情共用设置，刷新、返回其他地图、重新进入关卡页面后沿用；同源标签页同步。损坏存储使用默认值，存储写入失败仍能计算并提示仅本次生效。
- 奖励池中的多段 groups 是序列化分块，不是多次奖励。权重为零的条目不参与；普通确定池要求单项全权重，进度池须证明每个进度恰有一个互斥命中。随机池、额外活动状态／等级条件的奖励不累加为固定收益，页面提示其未计入。特殊间接结算项也不猜成经验或银币。
- 地图总收益按该地图各节点各结算一次汇总，所有节点使用同一进度和评价，不扣除入场资源，不把物品折算成银币。多节点地图在切换节点时显示本节点收益；单节点地图不重复显示节点收益。
- `assessment_type` / `assessment_value` 是旧解码器字段名，实际是分数区间上下界。等级字母来自 ArrangedStyle tag 51：B 51–69、A 70–91、S 92–100。对全部 1,274 节点和 25 档进度比较，92 与 100 的常规收益及可见物品掉落相同，因此只提供 S / A / B 三项。100 分专属表仅涉及多福莱尼第 10、20 图的隐藏 Fund 4184 / 4189「能量槽」（type 8，透明占位图），不是本页的可掉落物品或三种常规收益。
- 每个节点单独导出 `dropScores`，合并同一物品通过不同奖励分支获得的区间，不能把全局物品定义绑定到某一种评价。当前实际可见物品为“S”或“S / A / B”；卡片明确显示可掉落评价，选择不满足的评价时注明“当前评价不可掉落”，不从可能掉落列表中隐藏。评价达标不是必掉，活动条件仍可能限制掉落。
- 列表、地图总收益和本节点收益统一隐藏金额为 0 的银币、密码子。突袭／空袭的非零银币和密码子通过 `fixedCurrencyDrops` 合并进卡片与详情的掉落列表，不再重复显示收益栏；突袭 5 的密码子显示为 `×2,500`。计算仍复用原进度／评价规则，不写死金额；随机或额外活动条件奖励不冒充固定数量。其他评价才能获得的资源保留其正数数量和评价条件，不显示 `×0`。详情仍保留全局进度与评价切换。
- 活动地图进一步隐藏为 0 的指挥官经验，列表、地图总收益与每个节点同步应用；正数经验照常显示。三种固定收益全为 0 时隐藏空收益栏，仍保留进度／评价设置及未计入固定收益的提示。该展示规则不改变原始结算计算，也不修改其他分类的经验显示策略。

回归样例：哈尔科夫最高档各节点银币均为 5,200，经验依次为 1,500 / 1,500 / 2,100 / 1,500 / 1,500 / 2,100，总计 31,200 银币和 10,200 指挥官经验；24-4 第一节点最高档 S 评价为 1,345 经验、3,750 银币和 30 密码子。

### 突袭／空袭指挥官经验边界

不能把奖励表中没有 Craft 1 项解释为实际经验为 0。对 `analysis_apk/scout_native_trace/libasgame.device.so` 的追踪确认：

- `Quest_Set::getCompetitionExp`（`0x6f34e4`）返回 `max(本地 Craft 1 奖励合计, Quest_Set+0x60)`。
- `Quest_Set::ZC_ChallengeChapter_Ack`（`0x6f33a4`）在 `0x6f33fc` 从服务器应答偏移 `+8` 读取经验，随后在 `0x6f3408` 写入 `Quest_Set+0x60`。这不是可由本地地图奖励表推导的常量。
- 奖励类型 22 的 `generateAwardItem_Context_Faculty`（`0x6ed050`）属于单位上下文成长，不能误当指挥官经验；突袭 3 中的 3,129 也不能拿来代替指挥官经验。
- 普通突袭／空袭节点标记 `serverExperience`，该不确定性随地图总收益传播。按用户最终要求，卡片、详情均**隐藏指挥官经验项目**，不显示 0、不显示“服务器结算”占位，也不把用户一次实测的 10,600 固化为公式。银币、密码子的本地固定部分按上述规则并入掉落。

### 舞装头像合成

遵循 `ChapterUI.lua:2380–2404` 的舞装显示逻辑：Fund 标签匹配 Capsule，读取第一期外观模型对应的 ArrangedStyle `Head_Square`，叠加在 `GetFundResource(..., 5)` 的舞装箱底图上；不是直接使用列表里的长方形头像。生成器同时校验标签匹配结果与 Fund 的关联 Capsule ID 一致，每件舞装都必须解析到唯一的方形头像。

网页使用 SVG 两层原版图片合成，保留原图画布尺寸；以底图中心向右 13、向下 4 个原图像素定位，头像缩放至 25%，按游戏 Y 轴方向换算为 `skewY(-25)`。整体随掉落图标等比缩放，非舞装物品仍用原来的单层图标。回归覆盖全部舞装头像资源，以及 24-4 的 SU-18、SU-76、M3A1 对应关系和桌面/窄屏叠图边界。
