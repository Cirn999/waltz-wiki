# 研发路线纵向拖动修复

2026-10-31。复现车辆：T-60轻型坦克，完整路线65个容器、74条连接，画布5259×4322像素。

## 原因与修改

页面全局有 `html { scroll-behavior: smooth; }`。研发路线横向拖动使用逐帧 `translate3d`，纵向拖动则在同一帧中调用 `window.scrollTo(0, targetY)`。后者的默认 `auto` 会采用CSS平滑滚动；拖动不断更新目标，导致动画反复重启，画面落后于鼠标。实测24次拖动更新最多落后206像素，不能据此断言React渲染或研发图规模是主要瓶颈。

逐帧更新及松手时刷新最后一帧均改为 `window.scrollTo({ left: 0, top: targetY, behavior: "instant" })`。只改变拖动路径的滚动行为，保留请求动画帧合并、横向位移、页面正常导航的平滑滚动、完整路线和分享功能。不改变研发数据或布局。

## 验证

`npm run audit:research-chain-pan -- <本地网址>` 使用实际T-60完整路线，记录每次目标滚动位置与同步实际位置；验证向上、向下、水平、斜向、松手前尚有待处理帧及页面底部边界。位置误差须≤1像素，松手后不应残留滚动动画，横向位移须与指针一致。全局CSS仍应为smooth，避免将全站关闭平滑滚动当作修复。

本次向上／向下／水平／松手刷新／底部误差为0；斜向误差最多0.5像素（滚动像素取整）。这衡量位置跟随，不是FPS或所有硬件的帧率承诺。结果保存于 `.cache/research-chain-pan.json`。
