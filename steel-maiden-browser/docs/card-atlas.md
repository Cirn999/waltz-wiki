# 卡牌图鉴

入口为「钢舞姬 → 卡牌图鉴」，替代原「立绘卡片」。默认竖版卡牌，可一次切换全部为方形头像；两种模式共享顶部搜索、全局筛选与详情入口。默认按数值型内部编号升序排列；方形头像激活才艺筛选时按对应才艺等级降序，同级按编号升序，不改动属性表的排序状态。竖版初始载入 48 张，按需追加 48 张；方形头像一次显示全部筛选结果，不显示「继续载入」。人物素材仍延迟加载。

显示模式右侧另有「皮肤合并 / 皮肤分散」开关，初始为合并。合并时每车一个卡位，沿用右键选择与本地记忆；分散时默认立绘和每套皮肤各占一个卡位，同车先默认再依索引顺序展示皮肤，卡面下方标明皮肤名称。不在分散模式替换单个卡位，切回合并后恢复原先选择。两个开关独立，竖卡和方形头像都支持分散。

先按车辆筛选、编号排序，再展开皮肤；仅竖版最后按卡位分页（48 张），方形头像包括展开后的全部皮肤。切换合并/分散会重置竖版首批载入数量。分散模式同时显示车辆数与卡牌总数，皮肤索引加载失败时提示并可重试，不能将暂时未载入误报为无皮肤。

## 已确认的美术规则

- 原创细金属边框、肩章稀有度底托、右下军功章与延伸至底框的绶带使用已确认的位图，不重新生成或用 SVG 重绘。
- 蓝/紫/橙卡底色分别复用游戏 `kp-013`、`kp-015`、`kp-016`；保持预览采用的透明度、提亮和饱和度。
- 原版国籍图标在左上；车种图标在下方矩形车名栏左侧；稀有度图标在右上肩章内。
- 车名采用厚重黑体，在容器内水平、垂直居中，默认与皮肤共用同一规则。优先已确认断点，其次按「型号 / 完整车型词组」或「主名称 / 完整括号备注」拆行：如「鼠式 / 超重型坦克」「象式 / 坦克歼击车」「E-25 / （保时捷型）」。车型取最长完整词组，不能拆开「轻型坦克歼击车」「自行榴弹炮」等；完整英文型号、连续中文专名及括号内部不参与字数均分。仅在词间空白或安全的中英文边界换行；没有合适断点时保留一行并缩小字号。短型号内的 `(t)`、`(M)` 等标记不当成独立备注，原文全角/半角括号不改写。
- 人名使用已确认样稿的 SimSun 冷白宋体、深蓝描边，在右侧无底色的竖向区域居中；过长时缩小字号。显示固定的完整姓名图像，不再依赖客户端的宋体安装情况。
- 竖版卡框按魔改费用等级分三段：N1/2 铜铁、N3/4 银、N5/6 金；正负号不影响金属档次。蓝/紫/橙稀有度仍由原游戏背景和肩章标识表达，不能以魔改档次替代稀有度。
- 右下费用不再拼接 N/数字字符，而是按骰子式排列 1–6 颗通用金属星星。六种底纹沿用对应图纸的灰褐、铜红、金黄、蓝、绿、蓝紫；带正负号时，在固定右上位置加圆形金属铭牌，底纹与主星盘完全同源，圈色匹配卡框。N1、N2 无角标；N3 只有 N3、N3+；N4/5/6 各有低/中/高三档，共 13 档。
- 肩章标识按三张卡框各自的中线与原图透明留白定位（1024px 原图横坐标：铜 917、银 913、金 916.5），保留原标识尺寸与纵向位置。费用填充置于框下，星点与小铭牌置于框上，不遮挡星点。
- 方形模式直接使用 `TablePortrait`，保留头像框、稀有度、车种、费用及底部黑色遮罩，不另造头像组件。

位图目录：`public/art/card-atlas/`。导入脚本 `scripts/prepare-card-atlas-assets.mjs` 可从已确认的预览目录复制六份素材；运行程序不依赖该外部目录。原版立绘和图标继续读取 `maidens.json` 指定的本地资源。没有立绘时显示占位提示，详情仍可打开。

当前卡框/星盘素材位于 `public/art/card-atlas/cost-style/`，由 `prepare-card-cost-assets.mjs` 导入已确认的 13 张样稿所用图层，记录源图 SHA-256，仅裁透明边与编码 WebP，不重新绘制。三张全尺寸卡框和十二张可复用组件约 2.5 MB；运行只读取项目内文件。`cardAtlasCost.ts` 负责 13 档映射、星点/角标坐标和肩章居中，`CardCostMedal.tsx` 渲染这些位图；默认立绘与所有皮肤共用同一外框规则。未知费用不伪装为 N1，不显示错误星数。方形头像、属性表及筛选选项保持原有样式与数据。

布局：`app/card-atlas.css`；字符测量/排序：`app/cardAtlasLayout.ts`；卡牌与模式渲染：`app/CardAtlas.tsx`。车名仍优先使用 Bahnschrift/SimHei。人名由 `CardPersonName.tsx` 读取 `public/data/card-person-labels.json` 和 `public/art/card-atlas/person-names/`，保留可访问的姓名文本，姓名不匹配或图片加载失败时才回退到文字。

`prepare:card-person-labels` 在有 SimSun 的 Windows 上渲染完整姓名（非逐字字库），沿用样稿的 700 字重、`#f6f8fc` 冷白色、`#253747` 深蓝描边与轻阴影，使用高分辨率透明 PNG 缩放展示。777 位车辆共享 648 份姓名图，刷新全量数据时同步更新；运行和打包无需安装或联网下载字体。只分发完整姓名图像，不复制或转换 Windows 字体文件；图形输出依据 [Microsoft 字体使用 FAQ 的应用图像说明](https://learn.microsoft.com/en-us/typography/fonts/font-faq)。

## 方形头像才艺

只选一种才艺时自动按该才艺等级降序；选中多种时，在标题栏「清除条件」左侧出现降序依据下拉框，只列出当前已应用筛选的才艺。初始采用第一项；取消正在用于排序的才艺后，立即改用剩余第一项。复用属性表的 `compareTalentLevels`，同等级按内部编号升序；先排序再展开皮肤，同车皮肤保持相邻。竖版不显示此选项，继续按编号升序。清除才艺筛选后，方形头像也恢复编号顺序。

只有已应用的全局才艺筛选非空时，才在头像与车名之间的独立一行展示该车全部才艺与等级；三种才艺也必须左右排列，不换行。筛选框内未确认的操作不生效。被选中的才艺使用原版绿色轮廓底图，其他已拥有才艺仍显示图标和数字，但没有绿色底图。清除才艺筛选后移除整行。竖版、属性表头像不受影响。

`AtlasTalents.tsx` 复用 `CardUI.lua` 的叠放参数：图标 40%，绿色底图中心相对图标左下角为 (12,12)，数字为图标的子图层、缩放 150%（合成后为 60%）、中心位于 (图标宽度,8)。同一屏宽下各才艺标记等大，整行高度一致，自适应缩放保证三种才艺也横排完整显示。不修改原图，不使用文字模拟数字或 CSS 绿底。

方形图鉴的网格单元顶部对齐；头像在列方向上的自动边距归零，不参与剩余空间分配。车名、皮肤名换行只能向下增加单元高度，不能改变同一行头像的上下位置。

素材由 `prepare:atlas-talents` 从客户端 `UIStyle.dat` / `work` / `num` 图集中无损导出到 `public/art/atlas-talents/`，保留透明像素、旋转与原始未裁切画布。12 种才艺对应原图 `dg-016..021`、`dg-104..109`；绿色底图为 `dg-047..052`、`dg-116..121`，按客户端语义映射；数字 1–9 为 `kpxx-083..091`，0 为 `kpxx-092`。索引位于 `public/data/atlas-talents.json`。

`npm run audit:atlas-talents -- http://127.0.0.1:56501` 检查全部才艺类型、等级位图、单选/多选高亮和排序、取消草稿、皮肤合并/分散、全量头像与竖版分页，以及长名称头像对齐、三才艺横排和窄屏边界。

## 右键切换皮肤

有额外皮肤的卡牌/方形头像可右键打开皮肤菜单，选择带缩略图的皮肤或恢复「默认立绘」。两种模式共享每辆车的选择，本地保存至 `steel-maiden:atlas-skins:v1`，筛选、模式切换、离开页面或刷新后保留；没有皮肤的卡牌不拦截浏览器右键菜单。左键仍打开原车辆详情，不改变属性表、详情图库或配装。

竖版替换为该皮肤独立立绘，按自身模型取景（见下文），不套用默认模型偏移，也不统一缩小以容纳整张背景；恢复默认后仍用原生取景。方形头像替换为皮肤模型 `Head_Square` 的原版素材，复用 `TablePortrait` 的稀有度底框、稀有度标识、车种、费用和底部遮罩。现有 71 位车辆、88 套皮肤全部有对应头像。`prepare:skins` 同时更新皮肤头像和卡牌取景，也可单独运行 `prepare:skin-portraits`、`prepare:skin-card-framing`。

菜单支持 Shift+F10/菜单键打开、上下/Home/End 选择、Enter 确认、Esc 关闭，并限制在视口内；皮肤索引加载失败可重试，存储不可用时仍可在当前页面切换。资源索引：`public/data/maiden-skins.json`，头像目录：`public/art/skin-portraits/`。

## 验证

### 立绘取景

常规竖版卡牌按原生模型取景。`prepare-card-framing.mjs` 从客户端 RMC 的缩放/偏移、XML 骨骼与纹理锚点、plist 的原始画布/裁切/旋转信息重建立绘坐标，采用详情界面 `CreateHeadRole2(...,35)` 的缩放参数。长炮管等装备可被卡面裁切，避免人物随整张大图被缩小。

`app/cardAtlasFraming.ts` 将这些原生坐标映射到统一的竖版卡面视口（560 单位高，原点横向 47%、纵向 200 单位）。该视口是卡牌比例适配，不是逐像素复制游戏详情界面的窗口；原图、详情立绘、方形头像和卡框美术不变。

当前有 654 张静态立绘的原生坐标；其中 7002「迷你埃普西隆（俘获型）」经典 Q 版按用户确认单独改为与「外星吃货」相同的全宽、居中容纳方式，其余 653 张保持原生取景。这个卡牌层适配不修改原生元数据、原图、其他皮肤或方形头像，合并与分散模式均生效。121 张 Live2D 导出图，以及 2 张静态元数据不完整/结构不适用的卡牌保留原来的取景，原因记录在 `public/data/card-framing.json` 的 `fallback` 中，不套用未经验证的变换。完整数据导出会同步重新生成取景数据，离线程序运行时不需要解包目录。

经典 Q 版底部透明留白较多，不能只对齐图片外框：保持上述尺寸不变，仅在卡牌中下移画窗高度的 5.66%，使实际人物区域的垂直中心与「外星吃货」一致。校验脚本 `audit-epsilon-card-framing.mjs` 读取两张原图的有效 alpha 区域，在 320–1920px 视口检查可见人物上下位置，不裁切或改写原图。

皮肤独立使用 `public/data/skin-card-framing.json`，由 `prepare-skin-card-framing.mjs` 生成。它与默认卡牌共用 `native-portrait-geometry.mjs` 的原生静态坐标计算，并额外还原 `prepare-skins` 透明裁边的位移，再映射到同一个卡面视口。278「清凉水弹」不再因为沙滩、遮阳伞等背景被整体压小，人物线性尺寸较旧版完整容纳方式约增加 28%。原版立绘文件不变。

88 套已逐张截取实际卡牌检查：74 套采用自身原生坐标，4 套按已检查的人物区域适配（WZ-131 蛋糕师、雷诺 B1ter、KV-5 礼服、Pill-Box），另 10 套保留居中完整展示，包含紧凑 Q 版/非人形和已检查正常的 Live2D。KV-5 礼服的 PNG 尺寸与 plist 不符，不直接套用错误坐标。人工适配及原因显式记录在 `scripts/skin-framing-adjustments.json`，不冒充原生参数。上述调整不改变方形头像或详情页 PNG。
